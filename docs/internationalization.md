# 中英文国际化

界面支持 `zh-CN`（简体中文）和 `en`（English），中文产品名为 Tabbit 合辑，英文为 Tabbit Collections。

## 用户行为

- 设置中的语言选择立即生效，并保存在当前浏览器的本地存储；与 API Key 的保存、测试相互独立。
- 首次打开时优先使用浏览器语言。`zh-*` 使用简体中文，其他语言使用英文。浏览器存储被禁用时，仍可在当前页面切换语言。
- 同一来源下打开的页面会同步语言选择。扩展和本地网页预览分别保存偏好。
- 切换语言影响界面、提示、日期、数量和导出的界面文案。用户填写的标题、文件夹名、已有模型内容保留原文，不自动翻译或产生 API 用量。
- 新任务固定使用启动时的界面语言。任务执行途中切换界面语言，进度提示随界面切换，生成内容保持任务原有语言。
- 精选申请简介使用本次点击生成时的界面语言，可以为中文合辑生成英文简介，反之亦然。

## 文案资源

`shared/locales.ts` 是中英文产品文案的唯一来源。每个语义键包含 `zh-CN` 和 `en`，需要英文单数时补充 `enOne`。整句使用具名占位符，避免按中文语序拼接英文。品牌、数量、勋章、错误、进度、导出与插件元信息共用这份资源。

`shared/i18n.ts` 提供类型安全的消息键、插值、复数选择、语言解析、错误描述和进度描述。React 通过 `I18nProvider` / `useI18n` 获取当前语言。页面标题、描述和 HTML `lang` 会同步更新。

异常使用 `AppError(key, params)`。HTTP 和扩展消息传递 `errorDetails`，前端按当前界面语言翻译。未知错误使用通用文案，不展示第三方原始响应。任务保存 `messageDetails` 和 `errorDetails`，避免后台进度写死为某种语言。

## 语言传递

1. UI 从本地偏好或浏览器语言确定当前语言。
2. HTTP 请求携带 `X-UI-Language`；扩展消息携带 `locale`。
3. 创建任务同时在请求数据中携带 `locale`，校验后保存在 `Job.locale`。
4. 网页读取说明、分类主体、介绍、依据前缀、命名统一使用任务的 locale。
5. 保存合辑保留 `Book.locale`。旧任务和旧合辑缺少字段时兼容为中文，原有数据库和草稿键不变。
6. 精选申请简介单独携带当前语言；HTML 导出传入当前语言，设置 HTML `lang` 并包裹静态语言上下文。

服务端和后台任务不依赖全局可变语言，因此并发的中英文任务互不影响。

## 英文提示词与输出

系统、分类、网页介绍、命名、精选简介和格式重试的指令全部用英文维护于 `shared/prompts.ts`。各任务调用 `outputLanguage(locale)`，明确要求人类可读的生成字段使用指定界面语言，原始素材不能覆盖该要求。JSON 字段、类型枚举、ID、网址和专有名词保持原样。

中英文采用不同长度目标；英文网页介绍允许最多 650 个字符，中文最多 180 个字符。长度限制同时体现在提示词与响应校验中。国际化本身不增加模型调用次数。

## 构建和验证

扩展名称、描述和操作标题使用 Chrome 的 `__MSG_...__` 占位符；构建脚本从中央资源生成 `_locales/en`、`_locales/zh_CN`、`_locales/zh_TW`。后两者使用简体中文文案；扩展管理页的语言由浏览器决定。

测试覆盖翻译完整性、占位符一致、复数、默认与持久化语言、UI 渲染、HTTP/扩展传递、并发任务语言隔离、英文长度、证据前缀、旧数据兼容及精选简介的语言选择。使用模拟模型响应，不替代实际站点上的模型翻译质量评估。
