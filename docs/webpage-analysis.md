# 网页分类与介绍方案

Tabbit 合辑整理的是浏览器收藏的各种网页。文章只是其中一种内容形式。

## 产品行为

创建流程为：读取网页 → 识别网页类型和主体 → 按类型生成介绍 → 自动命名（用户未填写时）→ 确认并保存。

- 单个网页的介绍回答“这是什么、提供什么、为什么值得打开”，写法由内容类型决定。
- 工具讲用途和功能，文档讲覆盖范围和查阅任务，代码仓库讲项目目的，讨论讲问题和观点归属，资源目录讲收录范围和查找用途。
- 视频、播客或图库只依据已取得的文字材料介绍，不能声称看过、听过或理解了未提供的媒体。
- 编辑方向参与网页介绍和自动命名。它影响侧重点和受众，不得强行改写网页类型或补造事实；用户指定的合辑名称不被覆盖。
- 按任务启动时的界面语言生成 1–3 句介绍。中文通常 60–140 字、上限 180 字；英文通常 40–80 个单词、上限 650 个字符。材料不足可以更短。对元信息、仅标题或阻挡页，代码会额外添加同语言的依据说明。
- 界面统一使用“网页”“内容”“打开网页”。分类信息暂作为生成与保存数据，不增加类型筛选或新的操作入口。
- 精选申请简介使用点击生成时的界面语言，依据合辑标题、各网页类型和已有介绍概括用途，不默认是一组文章。中文通常 80–150 字，英文通常 50–90 个单词。超过 100 个网页时均匀抽取最多 100 个，并明确告知模型输入是样本。

## 类型与证据

`Source.pageAnalysis` 为可选字段，包含：

| 字段       | 含义                                           |
| ---------- | ---------------------------------------------- |
| type       | 网页的主要内容形式                             |
| subject    | 当前具体页面的主体或用途                       |
| confidence | high / medium / low，模型判断的置信度          |
| basis      | content / metadata / title / blocked，介绍依据 |

类型包括：article、documentation、tool、repository、video、audio、course、product、discussion、resource、website、profile、event、other、unknown。

同一域名的主页、文档和博客需要分别判断。网页自报的 og:type 只是线索。登录、验证码或错误页不能被当作目标网页内容，使用 unknown / low / blocked。

代码不会让模型提升抓取器实际拥有的证据：unavailable 固定为 title / low；metadata 最高为 medium；没有页面元信息时退至 title / low；模型自行选择更保守的依据时不会提升其依据等级。分类不保证正确，介绍阶段还要对照原始材料，不将推测升级为事实。

## 技术流程

1. 插件 DOMParser 和服务端 JSDOM 使用同一个 `readPageMetadata`，保留网页标题、描述、站点名、og:type 以及最多 12 条短标题。原有 Readability 文本提取和访问限制继续使用。
2. 每批最多 5 个网页、最多 2 批并发。分类调用使用每页最多 3,000 个文本字符及有界元信息，返回结构化分类。
3. 所有分类完成后，再分批调用介绍模型。每页使用最多 14,000 个文本字符，并附分类结果、对应类型的写作规则和编辑方向。
4. 两阶段响应都验证 JSON、字段范围、类型枚举和输入 ID 的一一对应。缺项、重复 ID、未知 ID 或无效类型会触发已有的格式重试；最多尝试两次，仍失败则报告失败，不静默漏掉网页。
5. 未指定名称时，根据类型、主体、简介、收藏语境和编辑方向命名。已有名称直接保留。
6. 分类与介绍随网页保存；提取正文和原始页面元信息不进入最终合辑。旧合辑缺少分类字段仍可使用，精选简介以已有信息保守概括。
7. 沿用现有任务状态，analyzing 内依次显示识别和介绍进度。取消或任一阶段失败后停止后续调用；不会将未完成结果标为可保存。

不含格式重试时，N 个网页的创建调用数为 `2 × ceil(N / 5)`，未填写名称另加一次。比如 10 个网页，原来简介需要 2 次，现在分类和简介共 4 次；自动命名再加 1 次。精选申请简介仍为单独一次按需调用。

## 提示词与实现位置

- `shared/prompts.ts`：英文编写的共用系统规则、分类、网页介绍、合辑命名、精选简介和格式重试提示；每阶段用 `outputLanguage(locale)` 指定用户界面语言。
- `shared/page-analysis.ts`：类型校验、证据降级和简介依据说明。
- `shared/analysis.ts`：分类 → 介绍 → 命名的调度和响应校验。
- `shared/page-metadata.ts`：两端共用的有界网页元信息提取。
- `shared/editorial-introduction.ts`：按需生成精选简介。

## 当前能力边界

本次不新增动态页面渲染、登录态采集、图片下载、媒体转录或图像理解。网页打不开时，分类提示词不能补出未读取的真实内容。网页提取仍可能误选登录页、导航或片段，模型只能在已提供的证据上辨别，不能保证识别全部异常。

后续接入图片时，可以利用已保存的类型和主体指导选图；仍需单独设计图片采集、授权、缓存和导出。

## 验证

使用模拟模型响应验证混合类型的阶段顺序、编辑方向传递、ID 映射与重试、资料不足时的依据降级、取消、分类保存和旧数据兼容；使用 HTML 夹具验证非文章页面的元信息。自动测试不调用真实模型，不能替代不同站点的真实生成质量评估。
